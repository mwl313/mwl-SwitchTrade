# A안 hostapd 하이브리드 구현 플랜 — 드라이버 확장 가능 구조

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** rtl8xxxu에서 beacon이 나가지 않는 문제를 hostapd 백엔드로 해결하되, **AP 엔진을 추상화**해서 향후 MT7612U(mt76) 등 다른 드라이버 추가 시 nl80211 백엔드를 끼워넣기만 하면 되는 구조로 만든다.

**Architecture:** `ApEngine` 추상 클래스(방 개설·광고·조인 감지의 공통 계약) 아래에 `HostapdApEngine`(현재 유일한 실구현, subprocess 관리 + config 생성 + ctrl interface 파싱)과 `Nl80211ApEngine`(향후 mt76 등 AP-native 드라이버용 스텁)을 둔다. 드라이버별 차이(hostapd config 옵션, 필요 권한, beacon 동작)는 `CardProfile` 레지스트리로 격리한다. HostTransport는 ApEngine 인터페이스만 알고, 어떤 엔진이든 동일하게 동작한다.

**Tech Stack:** Python 3.14 / asyncio / hostapd (subprocess + ctrl_interface UNIX socket) / ldn 0.0.17 (게임 프로토콜·TAP 유지) / 기존 framerelay 무수정

---

## 배경 (왜 이 구조인가)

- docs/19 확정: rtl8xxxu 드라이버는 NL80211_CMD_START_AP 단독으로는 periodic beacon 송출을 시작하지 않음 → hostapd의 전체 초기화 시퀀스가 필요
- hostapd의 compromise = 드라이버별 설정 차이 → 이것을 코드가 아니라 **데이터(CardProfile)**로 분리하면 새 카드 추가가 설정 한 줄이 됨
- ldn 0.0.17의 netlink binding에는 BEACON_IES 상수 자체가 없어 Python 직접 주입 불가(docs/18) → nl80211 백엔드를 지금 만들 수 없으므로 **스텁으로만 정의**하고 NotSupported 명시 (YAGNI)
- 기존 자산 재사용: `_build_host_beacon_head()`(docs/16), application_data 빌더(D1/D2/D3 수정 완료), TAP 경로, EchoGuard, rate limiter — 전부 그대로

## 핵심 설계

```
frlgsim/
├── ap_engine.py          # 신규: ApEngine 추상 클래스 + CardProfile 레지스트리
├── ap_hostapd.py         # 신규: HostapdApEngine (subprocess + ctrl 소켓)
└── transport.py          # 수정: HostTransport가 create_network 대신 ApEngine 사용

실행 흐름:
HostTransport.start()
  └─ engine = make_ap_engine(card_profile)      # 카드→엔진 선택 (레지스트리)
       └─ HostapdApEngine(iface, ssid, channel, ...)
            ├─ write_config()     # /tmp/hostapd_frlg_<ts>.conf 생성
            ├─ start()            # hostapd -B 실행, AP-ENABLED 대기
            ├─ wait_station()     # ctrl: AP-STA-CONNECTED <mac> 이벤트 대기 ← 조인 감지!
            └─ stop()             # 종료 시 정리 (SIGTERM → vif 정리)
  └─ 기존 ldn TAP/게임 프로토콜 경로는 그대로 (join은 스위치가 hostapd AP에 assoc한 뒤
     TAP 위에서 Pia/LDN 프레임으로 진행)
```

### CardProfile 레지스트리 (확장성 핵심)

```python
@dataclass(frozen=True)
class CardProfile:
    usb_id: str                 # "0bda:818b"
    name: str                   # "RTL8192EU"
    driver_hint: str            # "rtl8xxxu"
    preferred_engine: str       # "hostapd" | "nl80211"
    hostapd_opts: tuple[str, ...] = ()   # 드라이버별 hostapd 옵션 (예: ("ieee80211n=1",))
    notes: str = ""

CARD_REGISTRY: dict[str, CardProfile] = {
    "0bda:818b": CardProfile("0bda:818b", "RTL8192EU", "rtl8xxxu", "hostapd",
                             notes="START_AP-only beacon 미작동 — docs/19"),
    "0bda:8179": CardProfile("0bda:8179", "RTL8188EU", "rtl8xxxu", None,
                             notes="GUEST 전용 (docs/14)"),
}
# MT7612U 추가 시:
#   "0e8d:7662": CardProfile("0e8d:7662", "MT7612U", "mt76", "nl80211", ...)
# → nl80211 엔진이 스텀에서 실구현으로 승격되면 자동으로 그쪽 경로 탐
```

class HostapdApEngine(ApEngine):
    async def start(self, timeout_s: float = 15.0): ...

## Risks & Tradeoffs

| 리스크 | 완화 |
|---|---|
| hostapd와 ldn TAP 간 데이터 경로 불일치 | hostapd는 mgmt/인증만 담당, 데이터는 여전히 TAP(ldn-tap)로 — Step 9 실증 경로 유지 |
| 스위치가 오픈 AP 거부 | build_hostapd_conf가 WPA2-PSK 즉시 전환 지원 (Task 2에서 준비) |
| ctrl 소켓 권한 문제 | /var/run 대신 /tmp/hostapd-frlg/ 사용 + root 실행 |
| hostapd 미설치 환경 | 시작 시 `which hostapd` 체크 → 명확한 에러 메시지 + 설치 안내 |
| MT7612U nl80211 엔진 | 스텁만 제공(YAGNI). 실제 카드 확보 시 Task 1의 레지스트리에 프로파일 추가 + Nl80211ApEngine 실구현 |
