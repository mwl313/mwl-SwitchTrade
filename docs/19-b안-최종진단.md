# 19 — B안 최종 진단: rtl8xxxu START_AP beacon 한계 확정 (2026-08-22 밤)

> 상태: **B안(nl80211 시퀀스 모방)으로는 해결 불가능함을 실증적으로 확인**
> 결론: **A안(hostapd 하이브리드)으로 전환 필수**

---

## 최종 실험 결과

### 시도한 것 (전부 실패)

| # | 수정 | 결과 |
|---|---|---|
| 1 | BEACON_HEAD에 SSID/rates/DS IEs 추가 | probe response 시작, periodic beacon ❌ |
| 2 | BEACON_IES/PROBERESP_IES/ASSOCRESP_IES 주입 | ❌ nl80211 binding에 상수 없음 + 표준 값 충돌 |
| 3 | HIDDEN_SSID ZERO_CONTENTS→NOT_IN_USE | 적용 완료, beacon 여전히 ❌ |

### 관찰된 사실

| 항목 | hostapd | ldn create_network |
|---|---|---|
| START_AP 커널 응답 | ✅ 성공 | ✅ 성공 |
| Probe response 송출 | ✅ | ✅ |
| Vendor Action(LDN 광고) | N/A | ✅ 158개/40초 |
| **주기적 Beacon 송출** | ✅ **VM2에서 발견** | ❌ **0개** |
| mon vif 채널 공유 | ✅ AP와 동일 채널 | ❌ CH1 고정 분리 |

## 결론

**rtl8xxxu 드라이버는 NL80211_CMD_START_AP만으로는 beaconing을 시작하지 않습니다.**
hostapd가 보내는 추가 명령(아마 NL80211_CMD_SET_BEACON 또는 특정 attr 조합)이
드라이버의 beacon 타이머를 활성화하는 데 필요합니다. 이 명령은 netlink binding에
상수조차 정의되어 있지 않아 Python에서 직접 호출이 어렵습니다.

## A안 전환 결정

**hostapd 하이브리드 구조로 즉시 전환합니다:**

```
[hostapd] ← beacon 송출 (실증 완료) ← 방 개설·인증
    ↓ br0/bridge or monitor tap
[framerelay] ← 데이터 프레임 중계 (기존 그대로)
```

- hostapd 설정: FRLG 호스트 모드용 SSID(동적 hex), CH6, 오픈/WPA
- 기존 framerelay 코드 무수정 — 인터페이스만 ap0 등으로 지정
- HostTransport 대신 별도 스크립트로 통합

## 다음 세션 작업 (우선순위)

1. hostapd FRLG 호스트 설정 파일 생성
2. hostapd 기동 → VM2 스캔 → 스위치A 방 검색 확인
3. 스위치A 조인 → framerelay E2E 🏆
