# MWL-SwitchTrade — 로드맵 (v0.1)

> 목표: 순정 Switch NSO FRLG 인터넷 트레이딩.
> 원칙: **"똑바로 작동" 우선, 토큰/최적화는 마지막.** 각 Phase는 검증 가능한 결과물(데모)로 끝난다.

---

## Phase 0 — 환경 준비 (기반)

**목표**: PoC를 재현할 수 있는 환경 구축

- [ ] Linux 환경 확보 (브리지 PC용 — 주인님 Windows가 메인, Mac mini가 여분. Linux 필요 이유: LDN 라이브러리 + Wi-Fi 카드 드라이버)
- [ ] 호환 Wi-Fi 카드 확보 (후보: ALFA AWUS036ACHM [USB, 신뢰성 높음] 또는 RTL8821CE [PCIe])
- [ ] NSO FRLG 플레이 상태 준비 (디렉트 코너 해금까지, 약 20~40분 분량)
- [ ] .pk3 파일 준비 (PKHeX for Web으로 생성 — 브라우저에서 바로 가능)
- [ ] prod.keys 확보 여부 확인 (README 요구사항 — 순정 제약과의 충돌 리서치)

**완료 기준**: frlg-ldn-trade가 우리 환경에서 Switch↔PC 단독 트레이드 성공 (영상 데모 재현)

## Phase 1 — PoC 재현 + 코드 이해

**목표**: frlgsim 내부 구조 파악, 포크 준비

- [ ] frlg-ldn-trade 클론/포크 (GitHub: mwl313/skylink 또는 submodule)
- [ ] frlgsim 모듈별 역할 문서화 (transport/reliable/rfu/trade 흐름)
- [ ] 로컬 데모 성공 로그/설정 기록 (우리 환경 기준 재현 가이드 문서화)
- [ ] LDN 계층(kinnay)과 게임 계층(frlgsim)의 경계 확인 — 원격 피어로 라우팅할 지점 식별

**완료 기준**: 트랜스포트 교체 지점이 코드 레벨로 특정됨

## Phase 2 — PC↔PC 브리지 프로토타입 (LAN → 인터넷)

**목표**: 두 브리지 PC를 연결해 Switch A ↔ Switch B 트레이드

- [ ] 로컬(LAN) 테스트: 브리지 A/B를 직접 TCP 연결 → 게임 패킷 중계 → **같은 방에서 Switch 2대 트레이드 성공**
- [ ] 릴레이 서버 최소 구현 (세션 ID + Socket.IO/WebSocket 중계, Celio-Server 패턴)
- [ ] NAT 통과 검증 (홈 네트워크 2곳에서 테스트)
- [ ] 지연/타임아웃 측정 및 튜닝 (턴제 특성상 여유 있음 확인)

**완료 기준**: 서로 다른 네트워크의 Switch 2대가 인터넷으로 트레이드 성공

## Phase 3 — 세션 시스템 + 클라이언트

**목표**: 사용자 편의 — 방 만들기/참가하기

- [ ] 세션 ID 생성/공유 UI (6자리 코드 등 — GB-Link 방식)
- [ ] 클라이언트: CLI 우선 → 웹 UI (Windows 사용자 환경 고려)
- [ ] .pk3 관리 기능 (받은 포켓몬 저장, 보낼 포켓몬 선택)
- [ ] 연결 상태/디버그 표시

**완료 기준**: 브리지 PC 켜고 앱 하나 실행 → 코드 공유 → 트레이드

## Phase 4 — 확장 (선택)

- [ ] **온라인 배틀** (RFU 배틀 모드 — GB-Link가 증명한 실시간성 확인)
- [ ] **GSC (Gen 2) 트레이딩** (NSO GB 앱의 GSC — 프로토콜 리서치 후)
- [ ] 멀티 세션 (3인+ / 스타 토폴로지)
- [ ] 에뮬레이터 상대 지원 (RetroArch 등 — gblink-netplay-bridge 패턴)

## 우선순위 원칙

1. **똑바로 작동** — 각 Phase 끝에 눈으로 보이는 데모
2. 하드웨어 구매 결정은 최소한으로 (기존 장비로 가능한 것부터)
3. 닌텐도 정책 리스크는 Phase 2 이후 재평가
4. 실사용 환경(Windows) 고려는 Phase 3부터 — 코어는 Linux 무관하게
