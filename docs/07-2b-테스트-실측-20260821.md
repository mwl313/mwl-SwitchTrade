## 발견 사항 (실측)

1. **8192EU는 rtl8xxxu에서 LDN join 불가**
   - assoc까지는 성공 (dmesg: `RX AssocResp status=0`, `associated`)
   - 이후 암호화 단계에서 실패 → `deauthenticating by local choice (Reason 3)` (100ms 내)
   - 추가로 `Match already configured` (REGISTER_FRAME 중복) — 8188EU에선 미발생
   - 결론: rtl8xxxu의 8192EU 지원이 스테이션 모드에서 불완전 (8188EU만 검증됨)
   - 대안: `Mange/rtl8192eu-linux-driver` (1,432★, 2026-07-18) out-of-tree 드라이버

2. **스위치 실제 LDN comm-id = `0x01006fa0233f8000`** (FRLG 스위치 버전)
   - 코드 기본값 `0x0100610011000000`과 다름 → `--comm-id` 명시 필요
   - 두 스위치 모두 같은 comm-id 사용 → 구분 불가 (참가자 수/채널로 구분)

3. **USB authorized 토글이 카드 리셋으로 유효** (usbreset보다 확실, sysfs 경로 `/sys/bus/usb/devices/2-2/authorized`)
   - 리셋 후 phy 번호 증가 (phy0→1→2) — 스크립트에서 항상 감지

4. **NM unmanaged 미적용 상태에서 ldn은 EBUSY** — conf 파일은 재부팅으로만 적용. 임시 해결: `nmcli device set <iface> managed no` (즉시 적용)

5. **rtl8xxxu는 phy당 vif 1개 제한 경향** — wlx(monitor)가 점유 중이면 ldn의 vif 생성/프레임 등록 실패 (`Match already configured`). **ldn 실행 전 wlx 삭제 또는 down 필수**

6. **wlx 삭제 후에는 NM이 재생성 안 함** (unmanaged 상태) — ldn이 phy를 독점 가능

7. **카드 수신 사망 (부팅 직후/재시도 중)** — authorized 토글로 즉시 복구 (이번 세션에서 4회 재현/복구)

## ⭐ 드라이버 이슈 해결 (2026-08-21, 재부팅 후 재검증)

**결론: 8192EU는 rtl8xxxu(인커널)로 정상 동작한다. 이전 실패는 드라이버 문제가 아니라 stale 상태 문제였다.**

### 최종 실측 (bridge-b 재부팅 후)

| 시도 | 상태 | 결과 |
|---|---|---|
| 재부팅 전 (rtl8xxxu, 연속 시도) | assoc 성공 → status 1 → deauth | ❌ |
| 재부팅 후 (rtl8xxxu, 깨끗한 상태) | **스위치 B(GIRL)에 완전한 트레이드 세션 성공** | ✅ |

성공 로그 (guest, 8192EU):
```
[122.6s] host NI join status = JOIN_GROUP_OK (5)
[125.0s] host SEND_PLAYER_IDS playerCount=2
[127.0s] host LinkPlayer: GIRL v0x4005
[127.0s] RFU link ESTABLISHED (LinkPlayer 교환)
[134.8s] trainer card 교환 (P1_CARD_EXCHANGE)
[140.0s] host entered the trade room
```

### 원인 분석 (이전 실패들)

- `Match already configured` / EBUSY / `status 1` — 전부 **드라이버 재로드·연속 실행이 남긴 잔재 상태**에서 발생
- 재부팅 직후 깨끗한 상태에서는 3번째 시도에서 정상 성공
- rtl8192eu-linux(out-of-tree) 빌드도 성공했지만 **불필요** — rtl8xxxu로 충분 (오히려 out-of-tree는 모니터 모드에서 VM hang 재현)

### 운용 규칙 (실측 확정)

1. **카드 상태가 꼬이면 재부팅이 최선** (드라이버 재로드/연속 실패 후에는 잔재가 남음)
2. 재부팅 후: `modprobe -r 8192eu` (자동 로드된 경우) → rtl8xxxu 확인
3. ldn 실행 전: wlx/ldn vif 전부 삭제 (phy 독점)
4. 첫 시도 실패해도 재시도 (attempt 2~3에서 성공하는 패턴)
