## 3. T4 블로커 상세 (수정 대기 — 승인 후 진행)

### 현상
스위치 A·B가 **동시 광고**(같은 comm-id `0x01006fa0233f8000`, 각 1/6)일 때 host 조인이 3회 모두 실패:
```
saw network comm_id=... 1/6   ← 스위치 A
saw network comm_id=... 1/6   ← 스위치 B
RuntimeError: no joinable FRLG network (saw 2, 2 joinable)
```

### 원인 (transport.py 670~686행, 흐름 결함)
```python
net = comm-id 정확 매칭 방 찾기          # None (기본값 0x010061... ≠ 실제 0x01006fa...)
if net is None and len(joinable) == 1:   # 방 1개일 때만 폴백 → 2개라서 미적용!
elif net is not None and ...             # net=None이라 미적용
if net is None: error("no joinable")     # ← 여기로 빠짐
```
- T1~T3는 방이 1개라 폴백이 발동 → 못 본 케이스
- "같은 comm-id 2개면 최소 참가자 방 선택" 로직(8/21 패치)이 **comm-id 미매칭 경로에는 없음**

### 수정안 (~15줄, 리스크 낮음)
1. comm-id 매칭 방이 있으면 우선, 없으면 **joinable 전체가 후보**
2. 후보 ≥2면 **최소 참가자 방 선택** (기존 로직을 미매칭 경로로 확장)
3. `--target-bssid auto`는 선택된 방의 BSSID로 핀 (이미 검증됨)
4. 오프라인 테스트 추가(2방 동시 광고 시나리오) → 커밋 → VM 배포 → T4 재실행

- **조인 흐름 정정** (주인님 확인): EMU 조인 → 방 리스트 등록 → **EMU가 교환 신청 → 리더가 승인/거절** → 승인 시 트레이딩룸. 라운드 2의 "통신에러"는 이 승인 대기/타이밍과 무관하지 않았을 가능성 — T4 E2E에서 재확인

- VM1 SSH 간헐 타임아웃 (relay 경로 전환 시 수 분 끊김) — 테스트 자동화 시 재시도 필수
