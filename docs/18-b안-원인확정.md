## 핵심 발견

**ldn create_network의 START_AP는 성공하지만, rtl8xxxu 드라이버에서
periodic beacon 송출이 시작되지 않습니다.**

이것은 beacon head 내용물(IE)과 무관합니다. 증거:

| 시험 | Beacon 송출 | 비고 |
|---|---|---|
| hostapd (같은 카드, 같은 채널) | ✅ VM2 스캔에서 즉시 발견 | -15~-37dBm 강한 신호 |
| ldn START_AP + 패치된 head | ❌ ldn-mon에서 Beacon 0개 | Action 프레임(Vendor)은 다수 송출됨 |

## 상세 관측

### ldn START_AP 실행 시
- 커널에 NL80211_CMD_START_AP 전달 → **성공 응답** (에러 없음)
- Vendor Action 프레임(LDN 게임 방 광고): ✅ 158개/40초 송출 확인
- 802.11 Beacon 프레임: ❌ **0개**
- probe response: ✅ 동작 (VM2 active scan에 응답)

### hostapd 실행 시
- Beacon: ✅ 정상 송출 (VM2 스캔에서 발견)
- 차이: hostapd는 START_AP 외에 추가 nl80211 명령(BSS update, beacon interval set 등)
  을 연달아 수행. rtl8xxxu 드라이버가 이 추가 시퀀스를 필요로 하는 것으로 추정.

## D1+D2+D3 수정 검증 완료

host_long 기동 로그에서 application_data [21:35] 바이트 확인:
```
0101 0000 0301454d55
```
| 오프셋 | 값 | 스위치 대조 |
|---|---|---|
| [21:23] | `01 01` | ✅ 일치 (D1 플래그) |
| [26:31] | `03 01 45 4d 55` = TLV + "EMU" | ✅ 구조 일치 (D2 닉네임) |

→ application_data 자체는 이제 스위치와 구조적으로 동일.

## 결론

**문제는 소프트웨어(IE 누락)가 아니라 드라이버 레벨(rtl8xxxu beaconing 시작 조건)입니다.**

소프트웨어 수정으로 해결 불가능하므로:

## 해결 방법: hostapd 하이브리드 (A안)

```
[hostapd] ← beacon 송출 + 조인 인증 관리
    ↓ TAP 인터페이스로 데이터 전달
[framerelay] ← 프레임 투명 중계
```

- hostapd가 이미 설치돼 있고 beaconing 실증 완료
- FRLG 형식 SSID(16B hex) + WEP/WPA 암호 설정 가능
- 조인한 스위치의 데이터는 TAP으로 들어와 framerelay가 중계

## 다음 세션 작업

1. hostapd를 FRLG 호스트 모드용으로 설정 (SSID=동적 hex, WPA2-PSK)
2. HostTransport 수정: create_network 대신 hostapd 기동 + TAP 연결
3. VM1 배포 → VM2 스캔 → 스위치A 조인 → E2E

## 운영 노트

- ldn-mon은 AP 기동 후 up해야 AP 채널 공유 (선업 시 CH1 고정 버그)
- mon vif 채널 변경 시 "Device busy" → ip link down/up 후 재시도
- 8188EU는 세션마다 authorized 토글 필수
